## 无线迁移修正

首次实测能进入 OpenWrt，USB 串口密码登录及 PID 1 为 procd 均通过。
发现新 wifi-scripts 默认创建 `phy0-sta0`，且旧配置中的
`wifi-device.macaddr` 没有成为 STA 的实际地址。设备得到新的 DHCP 地址，
原 HA 卫星的 `wlan0` 身份检测因此失败。

板级包新增独立的一次性 `98-cmcc-lotus-hf-m10-wifi-compat`，版本为 `1-r8`：

- 仅处理本板 SDIO 控制器上的 `wwan` STA。
- 未明确指定接口名时保留应用使用的 `wlan0`。
- 从已有无线设备配置沿用本机 MAC，设置到 STA；不内置设备地址。
- 保留明确配置的接口名、STA MAC、SSID、密码及其他网络设置。
- 已占用的 `wlan0`、其他接口和无效地址不被覆盖，不重复分配地址。
- 使用新的 uci-defaults 文件名，使已运行过其他默认脚本的系统也能执行迁移。

增加 10 项回归测试；原有 45 项加新增测试共 **55 项通过**。
离线验证器同时核对 ROM 中迁移脚本与源码逐字节一致。

## 构建及刷写

完整原生构建通过。首轮软件包打包因沙箱禁止 fakeroot socket 而停止，
随后在宿主机权限环境继续通过；没有为此修改源码或更换工具链。
无线修正后在本 fork 中增量构建并再次通过离线配对、板型、启动源码和
90 个 AArch64 内核模块检查。

## 本轮通过的实机检查

- USB Loader 识别、从 fork 自带源码构建的临时助手重启进入 Loader。
- 两次写入后的整片 NAND 读回校验。
- 修正版启动，Rootfs 块设备 SHA-256 与最终候选一致。
- 型号 HF-M10、OpenWrt 25.12.5、Linux 6.12.108，PID 1 为 `/sbin/procd`。
- Squashfs `/rom`、ext4 `/overlay` 和原持久目录 `lotus-openwrt-v1`。
- USB CDC ACM 枚举，用户使用原密码完成 root 串口登录。
- SSH 密钥登录、LuCI 登录页。未认证的 LuCI 登录页返回 HTTP 403 并显示
  登录表单，这是本轮实际观测值；未使用或记录用户的网页登录密码。
- 原无线 MAC 和 `wlan0` 恢复，SDIO 实际时钟 50 MHz。
- 硬件服务和 HA 卫星自动启动；HA 服务监听端口恢复。
- ALSA 录放音设备枚举、蓝牙 HCI UP、温度、电池和温控节点读取。

额外通过一次 procd 普通重启：将本轮新增的两个无线兼容选项撤回为旧格式，
重新排队 ROM 自带的迁移脚本。重启后确认 boot ID 改变、迁移完成、
所有无线 UCI 选项的值与测试前一致，且 HA/硬件服务、SSH 和 LuCI 自动恢复。
